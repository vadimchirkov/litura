# Issues и применимые правки в чате

Разбор текущего рабочего дерева, 13 сентября 2026. Старое поведение Slop сверено с HEAD `3604507`. Это предложение интерфейса и границ реализации; в приложении пока исправлена только рекурсия открытия Issues.

## Рекомендация

Оставить один компактный вход **Review · N**. Внутри — короткий список цитат, сгруппированный в **Wording** и **Review**, а не длинное окно с повторяющимися объяснениями и кнопками у каждой строки. Выбор замечания закрывает список, показывает фрагмент и открывает одну карточку рядом с ним; на узком экране карточка появляется в существующем чате.

Из старого Slop стоит вернуть компактность и связь с обсуждением. Название Slop подходит для локальных языковых штампов, но плохо описывает замечания о смысле, повторениях и структуре. Не возвращать общий балл 0–100: автору нужнее конкретная цитата и причина. Повторное открытие списка не должно добавлять новые сообщения в историю чата, как делал старый score card.

Краткий ответ агента может содержать одну или несколько конкретных правок. Каждая получает карточку **Preview → Apply → Undo**. Применение вставляет уже показанный текст без второго запроса к модели. Объяснения и общие советы остаются обычным текстом. Если агент предложил направление, но ещё не написал замену, действие называется **Prepare rewrite**, поскольку сначала требуется получить текст.

## Поведение

- Верхний счётчик обозначает оставшиеся замечания. Внутри отдельно видны источник и состояние проверки: не запускалась, проверяется, завершена, результаты устарели. `0` не означает, что текст во всех отношениях хорош.
- Ограничение локального словаря английским показывается только у Wording. Оно не должно скрывать число замечаний модели в русском тексте.
- В списке: цитата и одна короткая причина. Подробное объяснение и действия — в выбранной карточке. Убрать из основного сценария метрики ритма, повторные счётчики и повторяющиеся дисклеймеры.
- Клик по подчёркиванию и клик по строке списка приводят к одной карточке. Между текстом, замечанием и обсуждением сохраняется понятная связь.
- **Keep original / Keep here** относится к текущему месту. Глобальное исключение выражения — отдельное действие **Ignore phrase everywhere**. Сейчас обычный Ignore имеет глобальный эффект, раскрытый только в tooltip.
- В чате клик по тексту ответа ничего не применяет. Есть явная кнопка Apply. Preview доступен кнопкой с клавиатуры и на сенсорном экране; hover может быть дополнительным сокращением.
- После Apply карточка показывает Applied и Undo. Чат остаётся открыт, остальные независимые правки сохраняются. Альтернативы одной и той же замены остаются взаимоисключающими.
- Само выделение фразы означает контекст вопроса. Запрос «почему это неясно?» должен приводить к обсуждению. Переписывание вызывается явно через Rewrite либо конкретную просьбу пользователя; не отправлять каждый вопрос с выделением в генерацию трёх вариантов.

Интерактивный пример иллюстрирует выбор замечания, предпросмотр, применение двух независимых правок, Keep original и Undo. Название верхней кнопки можно сравнить в настройках примера: Review / Issues / Slop. Модель, ввод новых сообщений и сохранение документа в этом примере не подключены.

## Как сделать предложения чата применимыми

### Контракт ответа

Сейчас `/chat` в `index.js:384` передаёт только SSE `{text}`, а `streamReply` в `src/app.js:2468` отображает Markdown. Системная инструкция даже просит дать текст для ручной вставки. Добавления кнопки под существующим ответом недостаточно: приложение не знает границы замены.

Минимальное расширение — обычный ответ плюс структурированные правки с `quote`, `replacement` и кратким `label`. Сервер и клиент связывают их со снимком документа, отправленным в запросе. Идентификатор документа, версия и позиции принадлежат приложению, а не выбираются моделью. Не извлекать команды из произвольного Markdown ответа.

1. Сохранить снимок документа и выделения при отправке сообщения.
2. Получить завершённые структурированные предложения одновременно с текстовым ответом. Способ передачи выбрать по возможностям уже подключённого провайдера; не добавлять отдельную модель для выделения правок из ответа.
3. Проверить схему, типы, ограничения размера и точное наличие цитаты в исходном снимке. Если выделение однозначно определяет фрагмент, проверить его. Без выделения принимать только уникальное точное совпадение. При нескольких одинаковых цитатах попросить выбрать место, не брать первое совпадение.
4. Только после завершённого и проверенного результата включить Apply. Обрыв SSE, Stop, некорректные данные или незавершённый блок не дают применимой карточки. Обычный текст ответа остаётся доступен.
5. Повторно проверить принадлежность документу и исходный текст перед применением. Выполнить одну транзакцию редактора, используя имеющиеся snapshot, save и Undo.

Не ослаблять глобально `replacementTarget` до поиска подстроки в текущем документе: это может перенести старую замену на другую одинаковую фразу. Сдвиг диапазона разрешён только через известные изменения документа. После загрузки другого документа, несопоставимой версии или редактирования самой цитаты — **Passage changed**, Apply отключён, доступен запрос новой правки.

### Границы первой реализации

Замены существующих непустых фрагментов, каждая применяется отдельно. Несколько независимых предложений допустимы; альтернативы одного места остаются одной группой. Вставку нового раздела, перенос блоков и Apply all лучше добавить после проверки базового сценария — для них нужно другое представление области изменения. Это не требуется для основного запроса «применить показанное решение».

## Альтернативы, которые не рекомендую

- Вернуть старый Slop 0–100 целиком: компактно, но число не помогает понять, что исправлять; старое открытие засоряет историю одинаковыми карточками.
- Назвать всё Slop: выразительно, но замечание о логике или недостающем обосновании не обязательно связано с шаблонным языком.
- Сделать отдельный постоянный менеджер Issues: дублирует текст, карточки замечаний и чат; в небольшом окне отнимает пространство у письма.
- На каждый Apply запускать rewrite: пользователь получит другой текст и лишнее ожидание вместо применения уже прочитанного решения.
- Сделать весь ответ кликабельным по аналогии с вариантом: ответ может содержать объяснение и несколько независимых изменений; действие должно иметь явную область.
